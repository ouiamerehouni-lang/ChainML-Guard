┌─────────────────────────────────────────────────────────────────────────┐
│ 📊 THRESHOLDS (computed from training data)                             │
└─────────────────────────────────────────────────────────────────────────┘

  age_p10       → 10th percentile of wallet age (days)
                  Example: 45.2 days
                  Trigger: "Very new wallet"

  tx_p90        → 90th percentile of transaction count
                  Example: 156 transactions
                  Trigger: "Unusually high transaction count"

  bal_p05       → 5th percentile of balance (ETH)
                  Example: 0.001 ETH
                  Trigger: "Unusually low balance"

  bal_p95       → 95th percentile of balance (ETH)
                  Example: 12.45 ETH
                  Trigger: "Unusually high balance"

  rate_p90      → 90th percentile of activity rate (tx/day)
                  Example: 2.34 tx/day
                  Trigger: "High activity for its age"

┌─────────────────────────────────────────────────────────────────────────┐
│ 🐛 TROUBLESHOOTING                                                      │
└─────────────────────────────────────────────────────────────────────────┘

  Problem: "Thresholds file not found" warning at startup
    Solution: Run python scripts/compute_thresholds.py

  Problem: No explanation section appears in UI
    Solution 1: Check thresholds.json exists in project root
    Solution 2: Check Flask console for errors
    Solution 3: Verify app.py has 'reasons' and 'disclaimer' in template vars

  Problem: Script fails with "dataset_final.csv not found"
    Solution: Ensure data/dataset_final.csv exists
    Solution: Check columns: balance, tx_count, age_days, is_fraud

  Problem: Thresholds seem wrong/unexpected
    Solution 1: Check dataset has enough samples (>1000 recommended)
    Solution 2: Verify dataset columns match expected names
    Solution 3: Check for data quality issues (NaN, outliers)

┌─────────────────────────────────────────────────────────────────────────┐
│ 🎯 KEY DESIGN PRINCIPLES                                                │
└─────────────────────────────────────────────────────────────────────────┘

  1. Data-Driven   → Thresholds from actual training data distribution
  2. Transparent   → Simple rules anyone can understand
  3. Cautious      → Always include disclaimer
  4. Maintainable  → Easy to modify thresholds/rules
  5. Robust        → Works even if thresholds.json missing
  6. Scoped        → Sender EOA only (matches paper)
